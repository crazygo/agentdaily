Flue - Agent Harness Framework for TypeScript

Flue is a TypeScript framework for building autonomous agents with a programmable harness architecture. Not another SDK - write once, deploy anywhere. Key features: (1) Agent = Model + Harness architecture similar to Claude Code and Codex; (2) Skills as reusable workflows with structured output using valibot schemas; (3) Session management like Claude Code with prompt tracking; (4) Fine-grained control over sensitive tokens and API keys; (5) Support for multiple sandboxes: virtual (zero-config), Daytona containers, Cloudflare Workers with R2; (6) Can deploy as HTTP server or run from CLI for local tasks and CI; (7) Built-in virtualization for filesystem operations - agents use read/write/grep tools regardless of whether target is local or remote. Philosophy: 'Stop renting someone else's agent' - build your own AI issue triage in 22 lines of TypeScript. Replaces Dosu, Greptile, CodeRabbit with owned stack.

May 2 GitHub

The Agent Harness Belongs Outside the Sandbox

Mendral argues that agent harnesses (the LLM loop) should run outside the sandbox, not inside. Architecture comparison: Inside (Claude Code local model) = loop lives in same container, simple execution, off-the-shelf harnesses work. Outside (Mendral's choice) = loop runs on backend, calls into sandbox over API. Tradeoffs of outside model: (1) Credentials stay out of sandbox - loop holds API keys, sandbox holds only workspace; (2) Can suspend sandbox when idle - saves cost, most agent work (thinking, API calls) doesn't need sandbox; (3) Sandboxes become cattle - if one dies, loop provisions new one and continues; (4) Multi-user becomes database problem, not distributed filesystem problem. Three problems solved: (1) Durable execution with Inngest for long-running sessions; (2) Sandbox lifecycle with Blaxel for 25ms resume from standby; (3) Filesystem virtualization - one interface (read/write/edit) routes workspace paths to sandbox, skill/memory paths to database. Key insight: Virtualized interface keeps API surface that models were trained on while adding database semantics where needed. Challenge: Bash is a leak - agents can run grep on /skills/ which bypasses virtualization.

Goodfire's Silico: Mechanistic Interpretability Tool to Debug LLMs

Goodfire released Silico, a mechanistic interpretability tool that lets developers debug and tweak LLMs by examining individual neurons and pathways. The company aims to make training AI models 'less like alchemy and more like a science' by exposing the internal knobs and dials of model behavior. Key features: (1) Zoom in on specific neurons or groups of neurons in trained models; (2) Run experiments to see what inputs make different neurons fire; (3) Trace pathways upstream and downstream to understand neural interactions; (4) Adjust parameters connected to individual neurons to boost or suppress behaviors; (5) Filter training data to avoid setting unwanted values during training. Real-world examples: Found a 'trolley problem' neuron in Qwen 3 that frames outputs as moral dilemmas when activated; Boosted transparency/disclosure neurons to flip a model's answer from 'no' to 'yes' (9/10 times) on whether a company should disclose deceptive AI behavior. Tool uses agents to automate interpretability work previously done by humans. Available for fee based on customer requirements. Targets smaller firms and research teams that can't afford in-house interpretability researchers.
